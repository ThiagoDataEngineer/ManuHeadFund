# Mudanças 2026-05-29

## Resumo
Sessão de 28/05 → 29/05: correções de qualidade no pipeline Mesa, anti-hallucination guards,
regime-aware whitelist, LLM provider state cache e normalização de regime_state.json.

---

## B29 — Mesa: regime vazio em mesa_drones.jsonl (orchestrator_v6.ps1 + mesa_agent.ps1)

**Problema:** 365/368 entradas no `mesa_drones.jsonl` tinham `regime=""` porque
`Context.regime` não existia como propriedade direta em todos os callers.

**Fix:**
- `orchestrator_v6.ps1`: injeta `triagem.regime` no Context antes de chamar `Invoke-Mesa`
- `mesa_agent.ps1`: extrai regime com fallback em 3 níveis:
  1. `Context.regime` (direto)
  2. `Context.regime_state.regime` (callers alternativos)
  3. `regime_state.json` no disco (fallback final)

---

## B30 — Mesa: rerun de drones degraded (mesa_agent.ps1)

**Problema:** Análise do `mesa_drones.jsonl` mostrou 16% das chamadas com
`drone_returned_empty` ou `job_state_Running_likely_timeout`.

**Fix:** Após execução paralela dos 3 drones, detecta falhos e executa rerun sequencial
(1 drone falho) ou paralelo (2+ falhos). Limite: 1 rerun por drone (sem loop infinito).

---

## B31 — Mesa LIDAR: direção hardcoded (mesa_agent.ps1)

**Problema:** LIDAR votava em direção diferente do `direction_proxy` porque o system prompt
não deixava claro que ele deve seguir o proxy, não decidir por conta própria.

**Fix:** System prompt reescrito com:
- Algoritmo obrigatório explícito (4 passos)
- Exemplos corretos e errados
- `vol_ratio` threshold ajustado de 1.0 para 0.37 (mais realista para altcoins)
- Proibição explícita de votar contra `direction_proxy`

## B32 — Anti-hallucination: DSR/n_trades como veto (lib_mentor_gate_block.ps1 + lib_mentor_rules.ps1 + mentor_agent.ps1)

**Problema:** LLM usava `"DSR n_trades=0 e track record inexistente"` como razão de ABORTAR
mesmo com `[DSR_HISTORY] INFO-ONLY` no gate block e regra explícita no system prompt.

**Fix:**
- 9 frases adicionadas ao guard `MENTOR_FORBIDDEN_PHRASES`:
  `"track record inexistente"`, `"track record zerado"`, `"zero track record"`,
  `"sem track record"`, `"DSR n_trades=0"`, `"n_trades=0 elimina"`, `"n_trades=0 significa"`, etc.
- `lib_mentor_rules.ps1`: regra 5 expandida com lista de frases proibidas
- `mentor_agent.ps1`: regras 5 e 6 adicionadas ao system prompt do Mentor
- Testes: `tests/dsr_forbidden_phrases.Tests.ps1` (38 testes)

## B33 — Anti-hallucination: BETA matemático (lib_mentor_rules.ps1 + mentor_agent.ps1)

**Problema:** LLM escrevia `"viola BLOCK"` quando `beta=1.38` e `cap_block=1.4`
(1.38 < 1.4 = não viola). Erro matemático causando ABORTARs indevidos.

**Fix:**
- Regra 6 adicionada: comparação numérica explícita com exemplos
- Formato correto obrigatório: `"beta=1.38 abaixo do BLOCK 1.4 (WARN acima de 1.1)"`

## Item 1 — Regime-aware tier_level na whitelist (lib_quant_whitelist.ps1 + scan_master.ps1)

**Problema:** Quando toda a whitelist estava em regime BEAR, os slots do top-10 eram
ocupados por ativos forçados com tier_level=1, bloqueando candidatos orgânicos do scanner.

**Fix:**
- `lib_quant_whitelist.ps1`: nova função `Get-MarketRegimeFromCache` (lê `regime_state.json`)
- `Merge-QuantWhitelistIntoCandidates`: aceita `$RegimeProvider` scriptblock opcional;
  ativos em `BEAR_STRONG` ou `BEAR_WEAK` recebem `tier_level=3` em vez de 1
- `scan_master.ps1`: passa `Get-MarketRegimeFromCache` como provider

## Item 2 — LivingWhitelist: provider primário mais leve (lib_living_whitelist.ps1 + promotion_weekly_cron.ps1)

**Problema:** `Build-MetricsProvider` buscava candles 4h + daily (pesado). O cron de
promoção semanal usava esse provider para todos os ativos do scan de discovery.

**Fix:**
- `lib_living_whitelist.ps1`: nova função `Get-LivingWhitelistMetrics` — busca apenas
  closes diários via CoinEx API, computa regime via `Compute-AssetRegime`, fail-soft
- `promotion_weekly_cron.ps1`: usa `Get-LivingWhitelistMetrics` como provider primário;
  cai para `Build-MetricsProvider` se função não disponível

## LLM Provider State Cache (warmup_llm_endpoints.ps1 + lib_claude.ps1)

**Problema:** Gemini com 429 persistente (8/9 warmups falhando). O cascade tentava
Gemini mesmo sabendo que estava em rate limit, gastando 15s de timeout.

**Fix:**
- `warmup_llm_endpoints.ps1`: registra status de cada provider em
  `journal/llm_provider_state.json` (`OK` / `RATE_LIMITED` / `DOWN`) com timestamp
- Pula Gemini no warmup se último status foi `RATE_LIMITED` há menos de 30min
- `lib_claude.ps1`: cascade consulta o cache antes de tentar Gemini;
  pula direto para Haiku se `RATE_LIMITED` há menos de 5min

## Normalização regime_state.json no daemon restart (scripts/daily_daemon_restart.ps1 + scripts/refresh_regime_state.ps1)

**Problema:** Python escreve `{current_regime, timestamp}` mas consumers PS precisam de
`{regime, phase, bias, updated_at}`. Schema incompatível causava regime="" em vários lugares.

**Fix:**
- `daily_daemon_restart.ps1`: chama `refresh_regime_state.ps1` antes do respawn dos daemons
- `scripts/refresh_regime_state.ps1` (novo): traduz schema Python → PS e salva no disco

## Fix INJUSDT inflado — regime-aware tier_level era no-op em produção (sessão tarde)

### Diagnóstico (avaliação de logs INJUSDT)

INJUSDT aparecia em **todos os ciclos** do `master_20260529.log` como `ABORTAR`,
sempre com `regime=BULL_STRONG direction=LONG` enquanto o mercado real estava em
BEAR (BTC=BULL_WEAK, XRP/SKY/SUI/BCH=BEAR_STRONG; `regime_state.json` global = `BEAR_WEAK`).

O LLM citava repetidamente a contradição como razão dominante de abortar:
`"phase=h24_p3_bear com bias BULL_STRONG cria contradição estrutural"`.

**Causa raiz (regressão introduzida hoje no commit `a251b44`):**
O fix "regime-aware tier_level" (Item 1, 28/05) deveria rebaixar ativos Tier A
forçados para `tier_level=3` em mercado bear, liberando o slot. Mas **nasceu como
no-op em produção** por descasamento de contrato entre dois arquivos do mesmo commit:

- `Get-MarketRegimeFromCache` procurava apenas **chaves por-mercado** no
  `regime_state.json` (`data.INJUSDT` ou `data.markets.INJUSDT`).
- `refresh_regime_state.ps1` grava apenas o regime **GLOBAL**
  (`{regime, phase, bias, current_regime}`) — sem chaves por-mercado.

Resultado: a função retornava `$null` para **todos** os markets, o `try/catch`
fail-soft engolia, e o rebaixamento nunca disparava. INJ (e todo Tier A) continuava
entrando `tier_level=1` + `score=100` forçado todo ciclo, inflando contexto, log e
consumo de LLM. Os testes originais passavam porque injetavam um `RegimeProvider`
mockado — o contrato real com `regime_state.json` nunca era exercido.

### Fix (Opção A — regime global como fallback)

`agents/lib_quant_whitelist.ps1` — `Get-MarketRegimeFromCache` agora, após não achar
chave por-mercado, faz fallback para o regime **global** (`.regime` → `.current_regime`).
Precedência preservada: chave por-mercado > regime global.

```powershell
# FIX 2026-05-29 (Opcao A): schema GLOBAL de producao.
if ($data.PSObject.Properties['regime'] -and $data.regime -and ($data.regime -is [string])) {
    return [string]$data.regime
}
if ($data.PSObject.Properties['current_regime'] -and $data.current_regime) {
    return [string]$data.current_regime
}
```

**Nota de semântica:** isso usa o regime **de mercado** (global), não o regime do
par. Ou seja, em mercado bear, INJ e todo Tier A caem para tier 3 mesmo que o par
esteja BULL_STRONG por pump recente — exatamente o comportamento pretendido pelo
fix original de 28/05.

### Validação contra produção real

```
Get-MarketRegimeFromCache INJUSDT (cache real journal/regime_state.json) = 'BEAR_WEAK'
INJ seria rebaixado para tier_level=3? True
```

Antes do fix retornava vazio (no-op). Agora retorna `BEAR_WEAK` → rebaixamento ativo.

### Esclarecimento (camadas que NÃO eram bug)

- INJ entrar forçado como Tier A LIVE (`score=100`): comportamento por desenho (whitelist curada, Sharpe 3.88).
- `score_predicted` (LLM) descolado do `scanner_score` (determinístico): separação deliberada desde EUREKA A (15/05). `score_predicted` é cosmético.
- O sistema estava abortando corretamente (não comprou o topo do pump). O problema era inflação de presença/contexto, não execução perigosa.

### Impacto esperado nos próximos ciclos

- Em mercado bear (regime global atual = BEAR_WEAK), INJ e todo Tier A forçado caem
  para `tier_level=3`, liberando slots do top-10 para candidatos orgânicos do scanner.
- INJ deixa de aparecer em todo ciclo monopolizando slot — reduz contexto/log inflado,
  consumo de LLM e os timeouts/INVARIANT_VIOLATION recorrentes do par.
- Quando o regime global voltar a BULL, Tier A volta ao topo automaticamente.
