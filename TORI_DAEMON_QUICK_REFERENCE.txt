HOW IT WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Every 4 hours:
  1. Scan 150 USDT pairs (1W, 1D, 4H, 1H timeframes)
  2. Detect trendlines (≥2 touches, 5-35° slope)
  3. Calculate 5-signal confluence score (0-100)
  4. Filter by threshold (≥80)
  5. Track entries, stops, targets
  6. Monitor for target hits / stop hits
  7. Update P&L
  8. Send Telegram alerts
  9. Save state (JSON)
  10. Sleep 4 hours + heartbeat every 5 min

Watchdog (every 30 seconds):
  • Monitor daemon heartbeat (should be <5 min old)
  • If stale (>10 min): auto-restart daemon
  • Max 3 restarts per session
  • Log all events

TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Issue: Daemon won't start
  → Check config.local.ps1 exists with COINEX keys
  → Check lib files exist (lib_tori_*.ps1, lib_coinex.ps1)
  → View startup log: Get-Content journal/tori_daemon_startup.log -Tail 30

Issue: Frequent crashes
  → View watchdog logs: Get-Content journal/tori_daemon_watchdog.log -Tail 50
  → Check if API timeout: increase SCAN_INTERVAL_MINUTES
  → Check network connectivity

Issue: No Telegram alerts
  → Verify TELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID in config.local.ps1
  → Bot must be member of chat
  → Test manually: . agents/tori_telegram_alerts.ps1; Send-TelegramMessage "Test"

Issue: Memory/disk growing
  → Check state file size: (Get-Item journal/tori_daemon_state.json).Length / 1MB
  → If >50MB: restart daemon (creates fresh state)
  → Archive old logs: tar -czf journal/logs_$(date +%Y%m%d).tar.gz journal/tori_*.log
